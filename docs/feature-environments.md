### Feature environments
An environment is a small, isolated lane at `<rootPath>/wt-<env>` and IS an octo-claude-pm lane: `<env>` is the lane name (lower-case, digits, `-`, e.g. `enum-null` or `kind-infra`), `wt-<env>` its lane folder; environments are discovered by `<rootPath>/wt-*/.octo/environment.json` (flat worktrees `wt-<lane>-<repo>` have none). It holds git worktrees of the changed repos (role `feature`, on `<user>/AB#<id>_<desc>`) and of the repos to rebuild against them (role `consumer`, detached at the base checkout's upstream commit, `origin/main`; `-localBase`: the local checkout's commit), its own `nuget/` feed, `.nuget-packages/` cache, `.octo/local-catalog` and `.octo/local-blueprint-catalog`, `logFiles/`, an `Octo.User.props` (`RestorePackagesPath`, `OctoEnvironment`, `OctoEnvironmentBase`; imports the base lane's props for its other settings) and `.octo/environment.json` (schemaVersion 1: name, workItem, base, created, owner, repos[name, role, path, branch, baseCommit, baseRef], slot - written only by octo-tools, read by octo-devstack). The folders keep the plain repo names, so `../nuget`, `../.octo/local-catalog`, `Find-OctoLaneRoot` and `Get-OctoBuildOrder` resolve inside the environment; plain `dotnet build`, Rider and `Invoke-Build` there are isolated without extra properties. `-branch wt-<env>` works in every lane cmdlet. Base lane (`Resolve-OctoEnvironmentDefaultBase`): `-base`, else `$env:OCTO_ENVIRONMENT_BASE`, else `branches/main` when it holds a lane (lanes layout), else `$rootPath` itself (flat layout, e.g. `~/RiderProjects/meshmakers/main`; manifest `base: "."`); a lane = `.octo/`, `Octo.User.props` or an `mm-*`/`octo-*` git checkout (not octo-tools/octo-devstack); none = error with a setup hint naming both layouts, `-base` and `OCTO_ENVIRONMENT_BASE` (also for a recorded base lane that is gone, `Get-OctoEnvironmentMissingBaseMessage`). In the flat layout `wt-<env>` lies inside the base lane (allowed: the lane's kill scope leaves `<lane>/wt-*` out); a base lane above `$rootPath` is refused, and a name whose `wt-<name>` already exists without a manifest (an octo-claude-pm lane folder or a flat worktree) is refused. The manifest's `path` is authoritative for every repo (in-place repos lie outside `wt-<env>`). Claims stay in the base lane, `branches/main/.octo/claims/<repo>.md`, with `Environment:` and `Worktree:` lines (format documented by octo-claude-pm); environments never create claims in their own folder. Module `modules/OctoEnvironment.psm1`, tests `tests/OctoEnvironment*.Tests.ps1` (nine `*.Tests.ps1` files; both layouts in `OctoEnvironment.Layouts.Tests.ps1`, flat fixture `New-FakeFlatWorkspace`; shared setup in `tests/OctoEnvironment.TestHelpers.ps1`). All cmdlets take `-env` and `-Json`.
- `New-OctoEnvironment -env <slug> [-repos <names>] [-workItem AB#..] [-branchName <git branch>] [-owner <text>] [-base <lane>] [-addAffected] [-localBase] [-skipPackageCacheSeed] [-WhatIf] [-Json]` - Creates the folder, the feature worktrees (an existing local/origin branch is checked out instead of created), props and manifest, and seeds feed and catalogs from the base lane (Sync rules). `-addAffected` adds every transitive consumer as a consumer worktree (needs `-repos`). Without `-repos` the environment starts empty (`-branchName` and `-addAffected` then are refused) - the way to adopt a hand-made environment: `New-OctoEnvironment -env <new> -workItem AB#..` then `Add-OctoEnvironmentRepo -env <new> -path <worktree> -inPlace`
  - Base (`Resolve-OctoEnvironmentBase`): a new feature branch (`--no-track`) and every consumer start from the upstream of the base checkout's current branch (`branches/main`: `origin/main`), fetched first; no upstream = origin's default branch (asked from origin with `git ls-remote --symref`; origin unreachable: the local `origin/HEAD`, `origin/main`, `origin/master`); a failed fetch uses the ref as last fetched (warning); no remote ref = local HEAD (warning). When the local HEAD differs: warning with repo and behind/ahead, `-Json` `baseDrift[{repo, role, baseRef, baseCommit, localCommit, behind, ahead}]`. `-localBase` = the local checkout's HEAD (the behaviour of earlier versions). Manifest: `baseCommit` = the commit the worktree started from (existing branch: its merge base with the base), `baseRef` = the remote ref the worktree started from (the upstream of the base checkout's branch or origin's default branch, e.g. `origin/main`, `origin/trunk`) | `HEAD` | the existing branch (null for adopted worktrees). Same for `Add-OctoEnvironmentRepo`
  - Network git calls (`Invoke-OctoEnvironmentGit -noPrompt`: `ls-remote` / `fetch` of the base, the default-branch check of `Remove-OctoEnvironment`, the feed snapshot) run as a child process with `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`, `GIT_SSH_COMMAND` = the configured ssh command (`GIT_SSH_COMMAND`, else `core.sshCommand`, else `ssh`; a `GIT_SSH` program is left alone) plus `-o BatchMode=yes -o ConnectTimeout=<min(30, timeout)>` (right after an `ssh`/`ssh.exe` program - OpenSSH takes an option's first value -, at the end of any other program; plink/TortoisePlink: `-batch`), stdin closed, and are stopped (process tree killed) after `$env:OCTO_GIT_NETWORK_TIMEOUT_SECONDS` (default 60, capped at 3600): result `TimedOut`, the base falls back to the ref as last fetched with a warning, after a timed-out `ls-remote` the fetch is skipped, and a host that timed out is skipped for 10 minutes by every later call of the module session (`$script:UnreachableGitHosts`, keyed by the remote's host; local paths never). Output pipes are read at most 5 s after git exits (a lingering ssh/credential helper cannot block). Reason: a console-less pwsh (agent tool) with Windows OpenSSH waits forever on a host-key or passphrase prompt. Tests `tests/OctoEnvironment.Windows.Tests.ps1` (local ssh stub, no network)
  - Feed snapshot (`-Json` `feedSnapshot{rebuildInEnvironment, staleProducers[{repo, behind, upstream, consumedBy}], hints}`): the feed is seeded from the base lane's packages, built from the LOCAL checkouts. `rebuildInEnvironment` = environment repos whose `baseCommit` is newer than the local checkout, from the whole manifest (Invoke-BuildEnvironment rebuilds them); `staleProducers` = libraries outside the environment that the `rebuildInEnvironment` repos consume (transitively; computed only when `rebuildInEnvironment` is not empty) and whose base checkout is behind its upstream (fetched) - add them as consumers, or update/rebuild the base lane and `Sync-OctoEnvironment`
  - Developer tools: `octo-tools` / `octo-devstack` resolve at `<rootPath>/<repo>` (not in the base lane) for `-repos` and `Add-OctoEnvironmentRepo -repo`; `Invoke-BuildEnvironment` never builds them (not in the range, an in-place one not in the kill scope), reports `environment.toolRepos`, and succeeds with nothing to build (events `plan` count 0 + `done`) when the environment holds only tools
  - Atomic: a call that does not complete rolls back its worktrees, the folder and the branches it created (never a branch that existed before; `Undo-OctoEnvironmentCreation`, `-Json` `rolledBack{worktrees, branches, folder, errors}`), so the same call is repeatable. `Add-OctoEnvironmentRepo` is repeatable, not atomic (what it added stays in the manifest)
  - Package cache: `<env>/.nuget-packages` is filled from a local cache instead of the network - the base lane's `.nuget-packages` when it has one, else `~/.nuget/packages` (`Get-OctoPackageCacheSeedSource`) - so the first restore does not download 2-5 GB. Everything except local builds: never `meshmakers.*/999.0.0` (the local builds come from the environment's feed) and never a version folder without `.nupkg.metadata` (unfinished extraction); existing folders of the environment are left alone. macOS on one APFS volume: clones (`cp -Rc`; copy-on-write - no time, no disk space, and nothing one environment does to its cache reaches another; measured once: the whole 19 GB user-level cache cloned in 13 s). Elsewhere a plain copy, made automatically only from the base lane's cache; never hardlinks (one file under two names: a write through one cache would change the other). `-skipPackageCacheSeed` turns it off; a failed copy is a warning, the environment is created. `-Json` `packageCache{source, target, method (clone|copy), packages, alreadyPresent, skippedLocalBuilds, skippedIncomplete, sizeBytes, seconds, errors, skipped}`
- `Initialize-OctoEnvironmentPackageCache -env <slug> [-source <cache>] [-WhatIf] [-Json]` - The same filling for an existing environment, or to top it up (repeatable; also the full copy from the user-level cache where cloning is not available). `-Json`: the `packageCache` fields at top level
- `Get-OctoEnvironment [-env <slug>] [-Json]` - Lists the environments; with `-env` also the git state of each worktree (exists, dirty, unpushed)
- `Add-OctoEnvironmentRepo -env <slug> -repo <name> [-role feature|consumer] [-addAffected] [-localBase] [-WhatIf] [-Json]` - Adds a worktree; `-addAffected` also adds, as consumers, the affected repos on the path from the feature repos to `-repo`
- `Add-OctoEnvironmentRepo -env <slug> -path <existing worktree> [-inPlace] [-role ..] [-WhatIf] [-Json]` - Adopts a linked worktree: an octo-claude-pm flat `<checkout>/wt-<lane>-<repo>` or a Claude Code `<repo>/.claude/worktrees/<name>` (repo = the owning main checkout, branch = its branch, baseCommit = merge base with the main checkout's HEAD; main checkouts are refused). Default: `git worktree move` to `wt-<env>/<repo>` (uncommitted changes move along; refused when git has it locked or a process runs from it - `Get-OctoProcessesUnderFolder` in `Invoke-KillDotnet.psm1`: the lane matching of Invoke-KillDotnet (cwd, entry assembly, modules), list-only over every process, so a shell, IDE or Claude Code session counts too; Windows cannot see working directories); reports `oldPath`/`newPath`. `-inPlace` only records it: `Invoke-BuildEnvironment` builds it from its folder with `RestoreSources=<env>/nuget;nuget.org`, `RestorePackagesPath=<env>/.nuget-packages` and `OctoLocalCatalogRootPath=<env>/.octo/local-catalog` as global properties, but **a plain `dotnet build` or Rider in an in-place worktree is not isolated** (it restores from the `../nuget` next to it). The `RestoreSources` passed for it are its `Directory.Build.props` evaluated for DebugL (`Get-OctoInPlaceRestoreSources`): the environment feed in place of `../nuget`, the repo's own sources (octo-report-services keeps Telerik; nuget.org when it declares none) and macros such as `$(OctoNugetPrivateServer)` substituted from the base lane's and the environment's `Octo.User.props` (a global property is not macro-expanded); a source with an unresolvable macro is dropped with a warning naming the macro. Credentials never reach the dotnet command line: `RestoreSources` carries the sources without them, an owner-only `NuGet.Config` in a temporary folder (mode 600 / current-user ACL, deleted after the build, also on failure) passed as `RestoreConfigFile` carries them plus the user-level `NuGet.Config`'s credentials for the same sources (e.g. Telerik), because `RestoreConfigFile` replaces that file. Feed URLs with credentials are masked in every output (`Hide-OctoUrlCredentials`). The environment's kill scope covers it. Remove only unregisters an in-place worktree, never deletes it (it belongs to its original owner)
- `Sync-OctoEnvironment -env <slug> [-WhatIf] [-Json]` - Snapshot refresh from the base lane, port of octo-devstack's `PrivateFeed` rules: missing packages copied, mirrored ones refreshed when the base changed, packages built in the environment always win; then `<env>/.nuget-packages/<id>/<version>` folders whose nupkg differs from the feed are purged. The catalogs follow the same rules; a `catalog.json` changed on both sides is JSON-merged (union by modelName/majorVersion or version, environment wins, latestVersion recomputed), a `cache/*-cache.json` changed on both sides is dropped. State in `<env>/.octo/sync/*.json`. `-Json` (also of `New-OctoEnvironment` and `Invoke-BuildEnvironment`) reports per feed/catalog the counts and at most 20 names per list (`truncated`); `-Detailed` lists every file. Never writes the base lane. Main's feed is copied, never added as a second source (same id/version in two local sources: NuGet takes whichever answers first)
- `Get-OctoAffectedRepos -env <slug> [-target <repos>] [-Json]` - Transitive consumers of the feature repos from a package graph of the base lane (environment worktrees replace their base folders): produced ids = packable csproj (`<PackageId>` or the project name; `<IsPackable>false</IsPackable>` produces nothing), edges = `<PackageReference Include="Meshmakers.*">` in csproj/props. Every csproj/props of the repo is read (projects outside `src/` count too); `node_modules`, `bin`, `obj`, `.git`, generated output (`dist`, `.angular`, `artifacts`, `coverage`, ...) and symlinks are never entered (measured once: about half a second for `branches/main`). `-target` keeps the repos on the path to the targets. Intermediate libraries must be rebuilt too, otherwise main's prebuilt packages bind to the new library at runtime (`MissingMethodException`)
- `Invoke-BuildEnvironment -env <slug> [-repos <names>] [-skip <names>] [-buildUnchanged] [-maxParallel <n>] [-refreshCatalogs] [-syncMain] [-verifyTests | -includeTests] [-EventsFile <file>] [-skipKill] [-DryRun] [-Json]` - Optional sync, then `Invoke-BuildRange -branch wt-<env>` from the environment's first to its last repo in the shared build order (frontends included; in-place worktrees via `-externalRepoPaths` at their position, with the global properties above via `-msbuildPropertiesPerRepo`). Packages land in `<env>/nuget`, the per-package purge hits only `<env>/.nuget-packages`. `-Json` returns Invoke-BuildRange's data plus `environment` and `synced` (and `sync`); events carry command `Invoke-BuildEnvironment` (`Invoke-BuildRange -EventsCommand`). `-DryRun` = `Invoke-BuildRange -WhatIf`, no sync. Use `-verifyTests` or `-includeTests` before every hand-off. Never publish feature work into `branches/main/nuget`
  - Only what changed is built (`modules/OctoBuildStamp.psm1`): after every successful repository a stamp `<env>/.octo/build-stamps/<repo>.json` records its git state (HEAD + diff of the tracked files + name and content of the untracked, not ignored files; `Invoke-Build.log` and ignored files do not count) and the SHA-256 of the environment-feed packages it consumes (the packages of every repo it depends on in the package graph, `Get-OctoUpstreamRepoMap`), plus whether the tests were compiled and a hash of the MSBuild properties of the build (`RestoreConfigFile` excluded). When a repository's turn comes and its stamp still matches, it is skipped; a library rebuilt earlier in the run changed the feed, so its consumers are built. The stamp is deleted before a repository is built - by every DebugL `Invoke-BuildRange`, also one without stamp switches - and written after it succeeded (build, tests, package copy), so a failed build never leaves a matching stamp; no stamp is written while the package cache holds another build of a consumed package (stale cache not purged), and a stamp that cannot be deleted stops the run. Also built: never built here, tests not compiled by the last build while this run asks for them, no `bin/DebugL`. `-buildUnchanged` builds everything - needed for what a stamp cannot see: a CK model taken only from the local catalog, npm packages of a frontend, `Octo.User.props`, the SDK
  - `-repos <names>` builds only these (still in build order), `-skip <names>` leaves repositories out (exact name or without `octo-`; a name that is no repository of the environment's build order, a developer tool included, is refused before anything runs). A left-out repository between a library that is built and a consumer that is built, or one that changed itself and has a built consumer, means stale packages: warning, `-Json` `staleWarnings[{repo, skipReason, changed, changeReason, upstreamBuilt, consumers, message}]`
  - `-Json`: `repositories[]` gain `status` (`built` | `skipped` | `failed`), `reason` (`unchanged`, `notSelected`, `excluded`, `nothingToBuild`, `neverBuilt`, `sourcesChanged`, `packagesChanged`, `propertiesChanged`, `testsNotCompiled`, `noBuildOutput`, `noGitState`, `configurationChanged`, `librariesBuilt` (a consumer app whose last build is older than the last build of `octo-frontend-libraries` in the environment), `always`) and `detail`; the document gains `skipUnchanged`, `builtCount`, `skippedCount`, `selection{repos, skipped{<repo>:{reason, detail}}, buildUnchanged}`, `staleWarnings`. `-DryRun`: `repositories[]` carry the prediction `action` (`build` | `skip`), `reason` (also `upstreamBuilt`: unchanged now, but a repository it depends on is built before it) and `detail`. Events: `plan.repos[]` gain `action`/`reason` (prediction), a repository with nothing to build keeps its `repoStart`/`repoDone` pair (status `skipped`), a repository left out as unchanged, not selected or excluded gets one `repoSkipped {repo, index, count, reason, detail}` instead of `repoStart`..`repoDone`, `repoDone` gains `status`/`reason`
  - Parallel (`-maxParallel <n>` (1..16), default 2 for `Invoke-BuildEnvironment`, 1 for `Invoke-BuildRange`; 1 = the sequential run, untouched code path): a repository starts when every environment repository it depends on in the package graph (`-repoInputs.dependsOn`, transitive) is finished - built, tests compiled, packages copied, cache purged, stamp written - and a slot is free. Each dotnet repository builds in its own child pwsh (`modules/scripts/Invoke-BuildRangeRepoWorker.ps1` -> `Invoke-OctoBuildRangeRepoStep`; job functions `Start-OctoRepoBuildJob` / `Get-OctoRepoBuildJobState` / `Stop-OctoRepoBuildJob`, mocked in the tests) that sets its own environment (lane `NUGET_PACKAGES`, `MSBUILDDISABLENODEREUSE`, the repository's `RestoreSources`), so nothing bleeds between builds; the compiler server stays shared as in the sequential run (`UseSharedCompilation=false` made real builds about three times slower when measured). The parent alone writes shared lane state, one step at a time: package copy (`Copy-OctoPackageFileAtomic`: temporary name without `.nupkg` in the feed folder, then rename - a restore never sees half a package), per-package cache purge (only the finished repository's packages; no running build restores them, its consumers have not started), build stamps, events, the CK intermediate-version sync. Dotnet repositories with a `ckModel.yaml` or `construction-kits.yaml` anywhere in the repository (`Test-OctoRepoUsesCk`) never overlap and keep their build order (CK publish into `<env>/.octo/local-catalog` stays serial); `build.ps1` / frontend / zenon repositories build alone, in-process. After a failure nothing new starts, running repositories finish (packages, stamp, `repoDone`), the rest is `notBuilt`; a throw or Ctrl+C kills the children. Without `-repoInputs` a repository depends on everything before it (sequential). Contract: `-Json` gains `parallel`, `maxParallel`, `failedRepos`; `plan` gains `parallel`, `maxParallel` and `repos[].dependsOn`; `-DryRun` `repositories[]` gain `dependsOn`, `exclusive`; `index` is the start order (1..count), `repoDone` repeats the index of its `repoStart`, events of running repositories interleave. The underlying `Invoke-BuildRange` switches are `-skipUnchanged`, `-recordStamps`, `-repoInputs @{ '<repo>' = @{ packages = ..; dependsOn = .. } }`, `-skipRepos @{ '<repo>' = @{ reason = ..; detail = .. } }` and `-maxParallel` (stamps in `<lane>/.octo/build-stamps`; without `-repoInputs` every other package of the lane feed counts as consumed; a plain `Invoke-BuildRange` neither writes stamps nor skips)
  - CK catalogs once per run (`modules/OctoCkCatalogRefresh.psm1`; also `Invoke-BuildRange`, `Invoke-BuildAll`, `Invoke-Build`): every CkCompile used to refresh the public and private CK catalog from the Pages mirror (about 190 sequential requests, 1-2.5 min, per CK project and again on pack; the engine's cache is valid for 60 s). Now the run reads them at most once - before the first repository that has a `ckModel.yaml` or `construction-kits.yaml` (`Test-OctoRepoUsesCk`), not at all while `~/.octo/ck-catalog/cache/*-github-catalog-cache.json` are younger than 30 minutes, else with `octo-ckc -c RefreshAllCatalogCaches` (lane build, base lane's, PATH) - deletes the lane's local-catalog cache file (the engine rebuilds a missing one from the folder and rewrites it after every publish) and builds those repositories with `OctoRefreshRemoteCatalogs=false`: CkCompile then resolves dependencies and the compatibility baseline from the caches as read at the start. Given up: a version published remotely during the run is seen by the next run. Not affected: the intermediate-version sync (OCTO-CK203) reads the private catalog itself. No octo-ckc or a failed read: nothing is switched off. Two runs that find the caches due at once (two environments): a lock file in the cache folder (`Enter-OctoCatalogRefreshLock`) lets one read and the other wait, then find them fresh; the engine writes a cache file atomically (temp + rename) and its readers retry, so a half-written cache is never read. `-refreshCatalogs` = every compile refreshes as before; a caller's own `OctoRefreshRemoteCatalogs` in `-msbuildProperties` is never overridden. CkRestore (`construction-kits.yaml`) refreshes unconditionally in the engine - not covered. The property is not part of the build stamp. `-Json` `catalogs{mode (fresh|refreshed|unavailable|failed|perCompile|notNeeded), usable, seconds, detail, repo}`; event `phase` `catalogs` for the repository that triggered the read
  - Timings: the dotnet step is `dotnet restore` + `dotnet build --no-restore` (`Invoke-OctoDotnetRestoreAndBuild`), so `repositories[]` and `repoDone` carry `restoreSeconds`, `compileSeconds`, `testRestoreSeconds` (restore of the test projects under `-verifyTests`) and `catalogSeconds` (the one catalog read, on the repository that triggered it); `buildSeconds` / `testSeconds` stay the whole steps. build.ps1 / frontend / zenon builds report 0 for the parts. `Invoke-Build -Json` gains `restoreSeconds`, `compileSeconds`, `catalogs`
- `Remove-OctoEnvironment -env <slug> [-WhatIf] [-Json]` - Removes the worktrees and what the environment owns (feed, cache, catalogs, logs, props, build stamps, manifest; anything else stays, the folder goes only when empty); in-place worktrees are only unregistered; refuses (removes nothing) when a worktree is dirty or has commits on top of its base commit that no remote has and whose changes are not on origin's default branch (fetched first; patch-equivalent commits - rebase merge -, every changed file identical or the whole change equal to one commit - squash merge -, or a PR of the branch merged into the default branch with HEAD as head via `gh` count as merged; the dirty state and HEAD are read again right before the removal; `-Json` per repo: `unpushedCommits`, `merged`, `mergedVia`, `mergedInto`, `pullRequest`, `unmergedCommits`, `mergeCheck`; the refusal names the unmerged commits; tests `tests/OctoEnvironment.RemoveMerged.Tests.ps1`). No `-force`. Feature branches are kept. Stop the environment's services first (octo-devstack `env_remove` does it). after the checks and before the first `git worktree remove` it stops the dotnet processes of `wt-<env>` (`Invoke-KillDotnet -action stop`, on every OS; in-place worktrees, other lanes, the daemon and non-dotnet processes never); a matched process still running refuses the removal; `-Json` `kill { roots, processes, killedCount, failed }`, `-WhatIf` lists them only (tests `tests/OctoEnvironment.RemoveKill.Tests.ps1`)
- Kill scope: `Invoke-KillDotnet -branchRootPath <rootPath>/wt-<env> -additionalRoots <in-place worktrees>` (run by `Invoke-BuildEnvironment` before the build - it stops the matched processes on Windows only, macOS and Linux list them -, `-skipKill` to opt out; `-additionalRoots` = further git repositories/worktrees matched with the same lane rule); main's scope (`branches/main`) never matches `wt-<env>` (prefix with trailing separator), and a lane's scope never matches its own `<lane>/wt-*` folders unless they lie under `-additionalRoots` (flat layout), and `wt-<env>` never matches `wt-<env>-<repo>`. The CK intermediate-version sync of an environment without the engine uses the base lane's `octo-ckc` before `PATH`
